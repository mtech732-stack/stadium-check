# فحص الملاعب — الاتحاد الكويتي لكرة القدم

تطبيق ويب لتعبئة **نموذج فحص واعتماد الملعب الرئيسي للأندية الكويتية** من الجوّال داخل الملعب،
ثمّ إخراج مطبوعة رسمية جاهزة للتسليم.

## التشغيل

```bash
node server.js
```

يطبع رابطين: أحدهما للحاسوب (`http://localhost:3210`) والآخر للجوّال على الشبكة المحلّية.

## البنية

| الملف | وظيفته |
|-------|--------|
| `js/data.js` | **مصدر الحقيقة**: المحاور الثمانية · ٣٧ بنداً · العبارات الجاهزة · الأندية · القياسات |
| `js/app.js` | التوليد من البيانات · الحالة · الحفظ التلقائي · التقييم وحالة الاعتماد |
| `js/print.js` | توليد المطبوعة الرسمية من حالة التقرير |
| `js/archive.js` | أرشيف التقارير · تقرير جديد · حذف · نسخة احتياطية واستيراد |
| `css/app.css` | واجهة التعبئة، جوّال أولاً |
| `css/print.css` | تخطيط A4 للمطبوعة ومعاينتها على الشاشة |
| `sw.js` · `manifest.webmanifest` | التشغيل دون إنترنت والتثبيت على شاشة الجوّال |
| `tools/make-icons.js` | توليد أيقونات PNG بلا اعتماديات (`node tools/make-icons.js`) |
| `server.js` | خادم ملفّات ثابت للتطوير والتجربة على الجوّال |

## تعديل النموذج

أيّ تغيير في بنود النموذج أو صياغتها أو العبارات الجاهزة يتمّ في **`js/data.js` وحده**.
بنية البند:

```js
{ n: 1, text: 'نصّ البند', phrases: ['عبارة جاهزة', '…'] }
```

وبند يحمل قيمة رقمية يضيف:

```js
num: { id: 'capacity', label: 'السعة المعتمدة', unit: 'متفرج' }
```

## التخزين

كلّ شيء في `localStorage` داخل الجهاز، ولا يغادره:

- `sc.reports` — كلّ التقارير `{ id: report }`
- `sc.current` — معرّف التقرير المفتوح
- `sc.prefs` — اسم الفاحص

النسخة الاحتياطية تُصدَّر ملفّ JSON من لوحة الأرشيف، وتُستورد منها.

## قواعد حالة الاعتماد

| الحالة | الاقتراح |
|--------|----------|
| بند «غير مطابق» أو قياس خارج مرجعه | غير معتمد |
| لا مخالفات ووجود «يحتاج معالجة» | معتمد بشروط |
| جميع البنود مطابقة | معتمد |
| البنود لم تكتمل | لا اقتراح |

الاقتراح **قابل للتجاوز يدوياً** دائماً.

## التشغيل دون إنترنت

عامل الخدمة (`sw.js`) يخزّن ملفّات التطبيق، **لكنّه لا يعمل إلّا على `localhost` أو على نطاق HTTPS**.
فالتشغيل عبر عنوان الشبكة المحلّية (`http://192.168.x.x`) يعرض التطبيق ولا يثبّته للعمل دون إنترنت.

عند تعديل أيّ ملفّ من ملفّات التطبيق، **ارفع رقم `CACHE` في `sw.js`** ليأخذ الجوّال النسخة الجديدة.

## بنود معلّقة

- تدقيق أسماء ملاعب الأندية في `js/data.js` (تقديرية حالياً).
- إضافة ترويسة الاتحاد الرسمية إلى المطبوعة إن لزمت.
- استضافة التطبيق على نطاق HTTPS لتفعيل التثبيت والعمل دون إنترنت.

## طقس النشر (إلزامي مع كلّ تعديل)

مع كلّ دفعة تعديلات، ارفع الأرقام الثلاثة معاً وإلّا بقيت أجهزة على نسخة قديمة:

1. `js/app.js` ← `const BUILD = N`
2. `version.json` ← `{ "build": N }` (نفس الرقم)
3. عناوين الملفّات `?v=N` في `index.html` و`sw.js`، ورقم `CACHE` في `sw.js`

**كيف يصل التحديث:** عند فتح التطبيق يسأل الخادم عن `version.json`؛ فإن كان الرقم
المنشور أحدث من `BUILD` العامل، مُسحت المخازن وأُلغي عامل الخدمة وأُعيد التحميل مرّة
واحدة تلقائياً. ورقم النسخة العاملة يظهر في أسفل لوحة «الأرشيف».

## ملفّات مؤرشفة

صفحتا «تعديل النموذج» و«المراجعة» أُخرجتا من التطبيق بعد أن أدّتا غرضهما،
وهما في `_legacy/` مع شرح سبب الإخراج وطريقة الاستعادة. لا يُحمّلهما أيّ جهاز.
